ループの 1 イテレーションを回します。対象: $ARGUMENTS

指定がなければ `docs/BACKLOG.md` の未完了項目のうち、**最も上にある 1 件だけ**を選んでください。
一度に複数の項目に手を付けないこと。スコープを広げるとレビューできなくなります。

### 1. 設計を宣言する
着手前に、以下を短く書き出してから始めてください。
- 何を作るか（ユーザーから見た振る舞い）
- 触るファイル
- 完了と判断する条件（テストで検証できる形で）

### 2. ブランチを切る
`git switch -c feat/<短い英語スラッグ>`（main で直接作業しない）

### 3. テストから書く
失敗するテストを先に書き、落ちることを確認してから実装に入ります。
CLAUDE.md の「テスト方針」に従うこと。DB はモックしない。

### 4. 実装する
CLAUDE.md の設計ルールを守る。ArchUnit が CI で強制するので、レイヤ違反は必ず落ちます。

### 5. 検証する
`make check` が緑になるまで直し切る。画面が変わる変更なら、実際に起動して確認する。

### 6. PR を出す
`gh pr create` で作成。テンプレートの項目を埋め、
**「何を変えたか」「なぜ必要か」「どう確認したか」**を具体的に書く。
画面が変わるなら、スクリーンショットを撮って貼ること。

### 7. 報告
PR の URL と、判断に迷った点・後回しにした点を報告して終了します。
